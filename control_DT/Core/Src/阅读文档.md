# 遥控器发端代码阅读说明

> 本文用于快速了解当前 STM32G431 遥控器发端工程的运行流程、输入处理和文件职责。完整引脚定义见根目录 [`IO.md`](../../IO.md)，输入电气约束见 [`controlIO.md`](controlIO.md)。

## 1. 当前工程状态

该工程正由原急停发端改造为无线遥控器发端。目前已经完成：

- 两只双轴摇杆的四路 ADC 采样；
- 摇杆 ADC 硬件校准、中心校准、低通滤波，以及 `-100～+100` 映射；
- 四路两档拨杆的八个数字输入配置、档位解码和消抖；
- 四个按键 SW1～SW4 的低有效输入配置和消抖；
- 三个 E34 无线模块的 UART、`M0/M1`、`AUX` 底层配置保留。

新的无线遥控控制帧格式已定义在根目录 [`无线控制帧协议.md`](../../无线控制帧协议.md)，并已由 `wireless_control.c` 组包后通过 E34-1 / USART1 发送。原 PA6 急停按键、EXTI 中断及 `ABCD` / `1234` 测试发送逻辑均已删除，PA6 现用作 SW3 按键输入。

## 2. 建议阅读顺序

1. [`main.c`](main.c)：程序入口、外设初始化和主循环调度。
2. [`main.h`](../Inc/main.h)：全部当前应用 IO 的宏定义。
3. [`gpio.c`](gpio.c)：拨杆、E34 `M0/M1/AUX` 等 GPIO 的实际初始化。
4. [`adc.c`](adc.c) / [`adc.h`](../Inc/adc.h)：四路摇杆 ADC1/ADC2 的底层配置。
5. [`joystick.c`](joystick.c) / [`joystick.h`](../Inc/joystick.h)：摇杆采样、滤波、中心校准和数值映射。
6. [`toggle_switch.c`](toggle_switch.c) / [`toggle_switch.h`](../Inc/toggle_switch.h)：四路两档拨杆的档位解码与消抖。
7. [`button.c`](button.c) / [`button.h`](../Inc/button.h)：四个低有效按键的读取与消抖。
8. [`wireless_control.c`](wireless_control.c) / [`wireless_control.h`](../Inc/wireless_control.h)：控制帧组装、CRC、E34-1 AUX 检查和 USART1 发送。
9. [`usart.c`](usart.c)：三个 E34 无线模块的 USART1/2/3 配置。

## 3. 程序运行流程

### 启动阶段

`main.c` 按以下顺序初始化：

```text
HAL_Init()
  └─ SystemClock_Config()
      ├─ MX_GPIO_Init()
      ├─ MX_ADC1_Init() / MX_ADC2_Init()
      ├─ MX_USART1_UART_Init() / MX_USART2_UART_Init() / MX_USART3_UART_Init()
      ├─ Joystick_Init()
      └─ WirelessControl_Init()
```

`Joystick_Init()` 会先进行 ADC1、ADC2 的单端硬件校准，再启动摇杆中心校准流程。

### 主循环（100 Hz / 每 10 ms）

```c
(void)Joystick_Update();
ToggleSwitch_Update();
Button_Update();
```

- `Joystick_Update()`：读取四路 ADC、更新滤波值、中心校准状态和 `-100～+100` 输出。
- `ToggleSwitch_Update()`：读取八个拨杆触点、解码四个两档拨杆，并通过连续 3 次一致采样完成软件消抖。
- `Button_Update()`：读取 SW1～SW4 四个低有效瞬时按键，通过连续 3 次一致采样完成软件消抖，并在每次有效按下时翻转对应的锁存状态。

`WirelessControl_Update()` 在主循环的每次迭代中运行。USART1 配置成功后以 10 ms 读取稳定输入快照、组装 [`无线控制帧协议.md`](../../无线控制帧协议.md) 规定的 9 字节帧，前面再加 3 字节目的地址；E22-1 的 AUX 为高且 UART 空闲时，通过 USART1 中断发送。配置失败则保持 20 ms。

## 4. 摇杆功能

### 引脚映射

| 信号 | MCU 引脚 | ADC 通道 | 原始字段 | 映射字段 |
|---|---|---|---|---|
| 左摇杆 X | PA0 | ADC1_IN1 | `debug.joystick.raw.left_x` | `debug.joystick.value.left_x` |
| 左摇杆 Y | PA1 | ADC1_IN2 | `debug.joystick.raw.left_y` | `debug.joystick.value.left_y` |
| 右摇杆 X | PA2 | ADC1_IN3 | `debug.joystick.raw.right_x` | `debug.joystick.value.right_x` |
| 右摇杆 Y | PA4 | ADC2_IN17 | `debug.joystick.raw.right_y` | `debug.joystick.value.right_y` |

### 数据对象

| 对象 | 数据范围 | 说明 |
|---|---:|---|
| `debug.joystick.raw` | `0～4095` | 最新 ADC 原始采样值。 |
| `debug.joystick.filtered` | `0～4095` | 一阶低通滤波后的 ADC 值。 |
| `debug.joystick.value` | `-100～+100` | 使用各轴校准中心值映射后的控制值。 |
| `debug.joystick.calibration` | — | 中心校准状态及四个记录的中心 ADC 值。 |

### 滤波和校准规则

- 一阶低通滤波：约 **75% 上次值 + 25% 本次采样值**，用于降低电位器抖动和 ADC 噪声。
- 上电后，程序在约 **320 ms** 内累计 32 个滤波样本作为四轴中位值；此期间应保持两个摇杆处于中位。
- 校准期间 `debug.joystick.calibration.in_progress == 1`，并且 `debug.joystick.value` 保持为 `0`。
- 校准完成且有效时，`debug.joystick.calibration.valid == 1`。
- 映射关系以每轴实际中心值为零点：ADC `0` → `-100`，中心值 → `0`，ADC `4095` → `+100`。
- 若需要重新校准，可调用：

  ```c
  Joystick_StartCalibration();
  ```

## 5. 四路两档拨杆

### 引脚映射

| 拨杆 | A 触点 | B 触点 |
|---|---|---|
| 1 | `A_1`：PB12 | `B_1`：PB13 |
| 2 | `A_2`：PA15 | `B_2`：PB9 |
| 3 | `A_3`：PC14 | `B_3`：PC13 |
| 4 | `A_4`：PA12 | `B_4`：PA11 |

八个触点均为 `GPIO_MODE_INPUT + GPIO_PULLUP`：拨到 A 或 B 时，对应触点通过开关接地并读为低；两个输入均为高或均为低都不是有效档位。

### 解码规则

| A 触点 | B 触点 | 状态 | 枚举值 |
|---|---|---|---:|
| 低 | 高 | A 档 | `TOGGLE_SWITCH_POSITION_A` (`-1`) |
| 高 | 高 | 无效状态（两触点均悬空） | `TOGGLE_SWITCH_POSITION_INVALID` (`2`) |
| 高 | 低 | B 档 | `TOGGLE_SWITCH_POSITION_B` (`1`) |
| 低 | 低 | 无效状态（两触点同时接地） | `TOGGLE_SWITCH_POSITION_INVALID` (`2`) |

直接解码结果保存在：

```c
debug.toggle_switch.raw.switch_1;
debug.toggle_switch.raw.switch_2;
debug.toggle_switch.raw.switch_3;
debug.toggle_switch.raw.switch_4;
```

可用于调试触点当前电平组合。实际业务应使用消抖后的稳定结果：

```c
debug.toggle_switch.state.switch_1;
debug.toggle_switch.state.switch_2;
debug.toggle_switch.state.switch_3;
debug.toggle_switch.state.switch_4;
```

新的原始档位必须连续 **3 次** 100 Hz 扫描一致才会写入 `debug.toggle_switch.state`，典型消抖延迟约 **20～30 ms**。因此拨杆切换瞬间的触点抖动、短暂无效状态不会立即改变稳定输出。

> **硬件注意：** PC13、PC14 已作为拨杆 3 输入，不能同时启用 LSE（32.768 kHz 外部低速晶振）。拨杆触点应只将 MCU 输入接到 GND，不应对这些输入脚施加超过 3.3 V 的外部电压。

## 6. 四个按键

四个按键都是内部上拉、**低电平有效**输入：释放时读取高电平，按下后由按键接地并读取低电平。

| 按键 | MCU 引脚 | 位置/用途 | 物理消抖字段 | 锁存状态字段 |
|---|---|---|---|---|
| `SW1` | PA3 | 右摇杆下方按键 | `debug.button.physical.sw1` | `debug.button.toggle.sw1` |
| `SW2` | PA5 | 左摇杆下方按键 | `debug.button.physical.sw2` | `debug.button.toggle.sw2` |
| `SW3` | PA6 | 其他按键 | `debug.button.physical.sw3` | `debug.button.toggle.sw3` |
| `SW4` | PA7 | 其他按键 | `debug.button.physical.sw4` | `debug.button.toggle.sw4` |

`debug.button.physical` 使用 `BUTTON_RELEASED`（`0`）和 `BUTTON_PRESSED`（`1`）表示释放/按下物理状态。每次消抖后的按键状态从释放变为按下时，对应 `debug.button.toggle` 在 `BUTTON_TOGGLE_OFF`（`0`）和 `BUTTON_TOGGLE_ON`（`1`）间翻转；上电默认全关，松手后状态保持，并由无线帧发送。直接 GPIO 解码结果位于 `debug.button.raw`，物理状态必须连续 **3 次** 100 Hz 扫描一致才会更新，典型消抖延迟约 **20～30 ms**。

## 7. 无线模块现状

| 模块 | 串口 | TX / RX | M0 / M1 | 当前状态 |
|---|---|---|---|---|
| E22-1 | USART1 | PA9 / PA10 | PB14 / PB15 | M0/M1 启动拉低，普通通信模式；控制帧主发送链路，发送前读取 PA8 AUX。 |
| E22-2 | USART2 | PB4 / PB3 | PB7 / PB6 | M0/M1 启动拉低，普通通信模式；当前未发送控制帧。 |
| E22-3 | USART3 | PB10 / PB11 | PB0 / PB1 | M0/M1 启动拉低，普通通信模式；当前未发送控制帧。 |

CubeMX 初始串口参数为 **9600、8N1**；E22 寄存器回读成功后，对应 MCU UART 切到 115200。应用层通过 `wireless_control.c` 从 USART1 发送；配置成功时周期为 10 ms，失败时保持 20 ms。当 E22-1 的 PA8 AUX 为低时跳过该发送周期。USART2、USART3 目前只参与上电配置，不发送控制帧。

## 8. 接收机控制帧速查

接收机从 E22 串口数据流中搜索固定 **9 字节**控制帧。定点模式会先剥掉地址头，MCU 看不到那 3 字节：

```text
A5 | VER:4 SEQ:4 | LY LX RY RX | SW | BTN | CRC8
```

| 偏移 | 字段 | 接收机处理方式 |
|---:|---|---|
| 0 | `A5` | 帧头；未匹配时继续在数据流中搜帧。 |
| 1 | `VER/SEQ` | 高 4 位必须为 `2`，低 4 位是序号 `0～15`。版本不对就重新搜 `A5`。 |
| 2～5 | `LY`、`LX`、`RY`、`RX` | 有符号 `int8_t`，范围 `-100～+100`；按该顺序解释，不能按 ASCII 字符处理。 |
| 6 | `SW` | 四个拨杆，每个占 2 bit：`01`=A 档，`10`=B 档，`00`/`11`=异常或无效，应执行安全处理。 |
| 7 | `BTN` | bit0～bit3 分别是 SW1～SW4 的锁存开关状态；bit4 是摇杆中心校准有效标志；bit5～bit7 必须为 0。 |
| 8 | `CRC8` | CRC-8/MAXIM；校验覆盖偏移 1～7 的 7 字节。 |

`BTN.bit0～bit3` 是**持续状态**，并非单次按键事件：`1` 表示对应按键业务状态当前为开，接收机不得在每一帧重复触发一次动作。`BTN.bit4 == 0` 时，四个摇杆数据应按零值或安全状态处理，不得执行依赖摇杆的危险动作。

接收机仅能在帧头、版本半字节和 CRC-8 全部正确后更新控制输出。若在项目约定的超时时间内未收到有效帧，或收到任一拨杆的 `00` / `11` 状态，必须进入预设的失联/安全状态。

## 9. 后续建议

1. 使用调试器核对四轴 `debug.joystick.raw`、`debug.joystick.filtered`、`debug.joystick.value` 及 `debug.joystick.calibration.valid`。
2. 核对 `debug.toggle_switch.state.switch_1` 至 `switch_4` 是否与实际 A / B 档位一致。
3. 核对 `debug.button.physical.sw1` 至 `sw4` 是否与实际按下/释放状态一致，并确认每次短按使对应 `debug.button.toggle` 翻转一次。
4. 明确四路拨杆和四个按键的业务含义。
5. 用串口抓包和接收端验证固定 9 字节控制帧：摇杆值、拨杆档位、按键状态、序号低 4 位和 CRC-8。
6. 在接收端加入帧校验、失联超时和安全停机逻辑；在安全联调完成前，不得将控制帧直接驱动危险执行机构。

## 10. CubeMX 重新生成注意事项

`WireSwitch.ioc` 已记录摇杆 ADC、拨杆 GPIO 和按键 GPIO。USART2、USART3 以及 E34-2/E34-3 的部分配置属于历史手动扩展；在 CubeMX 重新生成代码后，必须核对 `usart.c`、`gpio.c`、`adc.c`、`toggle_switch.c`、`button.c`、`wireless_control.c`、`debug.c` 和 CMake 源文件列表，避免手写配置丢失。
