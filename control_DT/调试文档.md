# 遥控器输入调试文档

> **适用范围：** 当前 STM32G431 遥控器发端代码。本文记录使用 STM32CubeIDE、Keil、VS Code + GDB 等调试器时，建议加入 Watch（监视窗口）的变量、正常取值及排查顺序。
>
> 当前固件以 **100 Hz（每 10 ms）** 扫描摇杆、拨杆和按键，并将稳定输入按 [`无线控制帧协议.md`](无线控制帧协议.md) 组装为控制帧，经 **E34-1 / USART1** 尝试以 50 Hz 发送；当 E34-1 的 AUX 为低时，本发送周期会跳过。

## 1. 无线发送调试

在监视窗口加入：

```c
wireless_control_diagnostics.tx_success_count
wireless_control_diagnostics.tx_error_count
wireless_control_diagnostics.tx_busy_skip_count
wireless_control_diagnostics.last_tx_status
```

正常连接并且 E34-1 的 `AUX` 为高时，`tx_success_count` 应约每 20 ms 增加一次。`tx_busy_skip_count` 增加表示模块在发送槽到来时尚未就绪；`tx_error_count` 或 `last_tx_status != HAL_OK` 表示 UART 提交失败。

## 2. 建议断点位置

建议在 `Core/Src/main.c` 的主循环中、三类输入更新函数执行完之后暂停：

```c
(void)Joystick_Update();
ToggleSwitch_Update();
Button_Update();
```

在 `Button_Update();` 后设置断点，或使用周期性暂停/实时 Watch，可在同一个时刻查看三类输入的最新结果。

> 单步调试会暂停 CPU，因此输入采样也会暂停。需要观察滤波、消抖过程时，建议使用非侵入式实时监视（Live Watch）或短暂停顿后继续运行。

## 3. 一次性加入 Watch 的变量

将以下变量直接加入监视窗口即可：

```c
joystick_raw
joystick_filtered
joystick_value
joystick_calibration

toggle_switch_raw_state
toggle_switch_state

button_raw_state
button_state
button_toggle_state
```

这些均为全局 `volatile` 变量，定义在对应头文件中：

| 输入类型 | 头文件 | 推荐观察变量 |
|---|---|---|
| 双摇杆四轴 ADC | `Core/Inc/joystick.h` | `joystick_raw`、`joystick_filtered`、`joystick_value`、`joystick_calibration` |
| 四路两档拨杆 | `Core/Inc/toggle_switch.h` | `toggle_switch_raw_state`、`toggle_switch_state` |
| 四个按键 | `Core/Inc/button.h` | `button_raw_state`、`button_state`、`button_toggle_state` |

## 4. 摇杆调试

### 4.1 推荐观察字段

```c
joystick_raw.left_y
joystick_raw.left_x
joystick_raw.right_y
joystick_raw.right_x

joystick_filtered.left_y
joystick_filtered.left_x
joystick_filtered.right_y
joystick_filtered.right_x

joystick_value.left_y
joystick_value.left_x
joystick_value.right_y
joystick_value.right_x

joystick_calibration.in_progress
joystick_calibration.valid
joystick_calibration.left_y_center
joystick_calibration.left_x_center
joystick_calibration.right_y_center
joystick_calibration.right_x_center
```

### 4.2 通道、引脚和字段对应关系

| 摇杆轴 | MCU 引脚 | ADC 通道 | 原始/滤波字段 | 映射字段 |
|---|---|---|---|---|
| 左摇杆 X | PA0 | ADC1_IN1 | `left_x` | `left_x` |
| 左摇杆 Y | PA1 | ADC1_IN2 | `left_y` | `left_y` |
| 右摇杆 X | PA2 | ADC1_IN3 | `right_x` | `right_x` |
| 右摇杆 Y | PA4 | ADC2_IN17 | `right_y` | `right_y` |

### 4.3 字段含义与正常范围

| 变量 | 取值范围 | 含义与正常现象 |
|---|---:|---|
| `joystick_raw.*` | `0～4095` | 最新的 12 位 ADC 原始值。摇杆移动时应立即向低端或高端变化。 |
| `joystick_filtered.*` | `0～4095` | 滤波后的 ADC 值。相对 `joystick_raw.*` 会更平稳，但在快速拨动时会有少量跟随延迟。 |
| `joystick_value.*` | `-100～+100` | 以本轴校准中心值为 0 映射后的控制值。居中应接近 `0`，两个行程端应接近 `-100` 和 `+100`。 |
| `joystick_calibration.in_progress` | `0` / `1` | `1` 表示正在采集中心值；启动或重新校准后保持约 320 ms。 |
| `joystick_calibration.valid` | `0` / `1` | `1` 表示四轴中心校准有效，`joystick_value` 已可用。 |
| `joystick_calibration.*_center` | `512～3583` 为有效范围 | 各轴自动记录的 ADC 中位值；典型硬件中位值通常接近 `2048`，但以实际读数为准。 |

### 4.4 上电校准检查步骤

1. 两个摇杆保持在物理中位后上电或复位。
2. 先观察 `joystick_calibration.in_progress`：启动后应为 `1`。
3. 约 **320 ms** 后，应变为：

   ```c
   joystick_calibration.in_progress == 0
   joystick_calibration.valid == 1
   ```

4. 此时四个 `joystick_calibration.*_center` 应在 `512～3583` 内，且通常接近 `2048`。
5. 摇杆仍处于中位时，四个 `joystick_value.*` 应接近 `0`。
6. 分别拨动每个轴到两端，确认对应 `joystick_value.*` 能接近 `-100`、`+100`。

> 正负方向由电位器接线方向决定。例如向上得到 `+100` 或 `-100` 都不表示 ADC 故障；后续定义控制协议时再统一规定各通道正方向即可。

### 4.5 重新校准

需要在调试器表达式窗口或临时测试代码中重新执行中心校准时，可调用：

```c
Joystick_StartCalibration()
```

调用后应立即看到：

```c
joystick_calibration.in_progress == 1
joystick_calibration.valid == 0
joystick_value.left_y == 0
joystick_value.left_x == 0
joystick_value.right_y == 0
joystick_value.right_x == 0
```

保持摇杆居中约 320 ms 后，再检查 `joystick_calibration.valid == 1`。

### 4.6 摇杆异常定位

| 现象 | 优先查看的变量 | 可能原因 |
|---|---|---|
| 某一轴始终为 `0` 或 `4095` | 对应 `joystick_raw.*` | 模拟信号断线、短接到 GND/3.3 V、摇杆未供电、ADC 引脚配置错误。 |
| 原始值变化但控制值不变化 | `joystick_calibration.valid`、`joystick_value.*` | 中心校准未完成或无效。 |
| 中位时控制值明显不为 0 | `joystick_filtered.*`、`joystick_calibration.*_center`、`joystick_value.*` | 上电校准时摇杆未居中；重新执行 `Joystick_StartCalibration()`。 |
| 原始值跳动明显 | `joystick_raw.*` 与 `joystick_filtered.*` | 检查摇杆电源、地线共地、模拟线连接和硬件噪声。 |
| 滤波值比原始值变化慢 | `joystick_raw.*` 与 `joystick_filtered.*` | 正常现象：当前滤波为约 75% 历史值 + 25% 新值。 |

## 5. 两档拨杆调试

### 5.1 推荐观察字段

```c
toggle_switch_raw_state.switch_1
toggle_switch_raw_state.switch_2
toggle_switch_raw_state.switch_3
toggle_switch_raw_state.switch_4

toggle_switch_state.switch_1
toggle_switch_state.switch_2
toggle_switch_state.switch_3
toggle_switch_state.switch_4
```

### 5.2 拨杆引脚

| 拨杆 | A 触点 | B 触点 |
|---|---|---|
| 拨杆 1 | PB12 (`A_1`) | PB13 (`B_1`) |
| 拨杆 2 | PA15 (`A_2`) | PB9 (`B_2`) |
| 拨杆 3 | PC14 (`A_3`) | PC13 (`B_3`) |
| 拨杆 4 | PA12 (`A_4`) | PA11 (`B_4`) |

所有触点均使用内部上拉、低电平有效：未接地时为高电平，拨到对应端时该端接地并读为低电平。

### 5.3 枚举值解释

| `toggle_switch_*_state.switch_n` 值 | 枚举名 | A/B 输入电平 | 含义 |
|---:|---|---|---|
| `-1` | `TOGGLE_SWITCH_POSITION_A` | A 低、B 高 | A 档 |
| `1` | `TOGGLE_SWITCH_POSITION_B` | A 高、B 低 | B 档 |
| `2` | `TOGGLE_SWITCH_POSITION_INVALID` | A 高、B 高或 A 低、B 低 | 无效状态；两档拨杆不应长期出现。 |

### 5.4 原始值与消抖后值

- `toggle_switch_raw_state`：本次扫描直接解码的结果，用于确认触点和接线。
- `toggle_switch_state`：消抖后提供给后续业务的稳定结果。
- 新档位需要连续 **3 次** 扫描一致才会写入稳定结果；扫描周期为 10 ms，因此正常切换时，稳定值相对原始值有约 **20～30 ms** 延迟。

### 5.5 拨杆异常定位

| 现象 | 优先查看 | 可能原因 |
|---|---|---|
| 长期显示 `2`（高/高） | `toggle_switch_raw_state.switch_n` | A/B 触点均悬空；检查开关公共端是否接 GND、接线是否断开或拨杆型号是否正确。 |
| A、B 两端显示反了 | `toggle_switch_raw_state.switch_n` | A、B 两根信号线接反；可调整接线或后续调整业务定义。 |
| 长期显示 `2`（低/低） | `toggle_switch_raw_state.switch_n` | A、B 两端同时被接地，或拨杆型号/接线方式不符合两档独立触点假设。 |
| 原始值正确，稳定值未立即改变 | 原始与稳定变量同时观察 | 正常消抖过程；保持档位超过约 30 ms 后应更新。 |

## 6. 按键调试

### 6.1 按键和字段对应关系

| 按键 | MCU 引脚 | 位置/用途 | 原始字段 | 物理消抖字段 | 锁存状态字段 |
|---|---|---|---|---|---|
| SW1 | PA3 | 右摇杆下方按键 | `button_raw_state.sw1` | `button_state.sw1` | `button_toggle_state.sw1` |
| SW2 | PA5 | 左摇杆下方按键 | `button_raw_state.sw2` | `button_state.sw2` | `button_toggle_state.sw2` |
| SW3 | PA6 | 其他按键 | `button_raw_state.sw3` | `button_state.sw3` | `button_toggle_state.sw3` |
| SW4 | PA7 | 其他按键 | `button_raw_state.sw4` | `button_state.sw4` | `button_toggle_state.sw4` |

### 6.2 值的解释

| 值 | 枚举名 | GPIO 电平 | 含义 |
|---:|---|---|---|
| `0` | `BUTTON_RELEASED` | 高电平 | 按键释放（默认状态）。 |
| `1` | `BUTTON_PRESSED` | 低电平 | 按键按下，按键将输入接到 GND。 |

### 6.3 消抖检查

```c
button_raw_state.sw1     // 直接读取 GPIO 的结果
button_state.sw1         // 连续 3 次一致后的物理按键状态
button_toggle_state.sw1  // 每次有效按下后翻转的开/关业务状态
```

其余按键同理。新的原始按键状态连续 **3 次** 100 Hz 扫描一致后，物理状态才更新，典型延迟约 **20～30 ms**。每次 `button_state.swN` 从 `0` 变为 `1` 时，`button_toggle_state.swN` 在 `0` / `1` 之间翻转；松手后锁存状态不变。

| 现象 | 优先查看 | 可能原因 |
|---|---|---|
| 释放时显示 `1` | `button_raw_state.swN` | 输入被接地、按键常闭/接线错误，或外部电路拉低。 |
| 按下时仍显示 `0` | `button_raw_state.swN` | 按键未将引脚接到 GND、信号线断开或引脚不对应。 |
| 原始值变化但稳定值短暂不变 | 原始与稳定变量同时观察 | 正常消抖过程；持续按下/释放超过约 30 ms 后应更新。 |
| 按下后业务状态没有翻转 | `button_state.swN`、`button_toggle_state.swN` | 有效按下时间不足约 30 ms，或未出现从释放到按下的稳定边沿。 |

## 7. 完整输入验收顺序

1. **检查摇杆电气连接**：两个摇杆为 0～3.3 V 输出，MCU 与摇杆共地。
2. **复位并保持摇杆居中**：等待约 320 ms，确认 `joystick_calibration.valid == 1`。
3. **逐轴检查 ADC**：拨动四个方向，确认对应 `joystick_raw.*` 变化，且没有其他轴异常跟随。
4. **检查滤波与映射**：确认 `joystick_filtered.*` 平稳、`joystick_value.*` 居中接近 0、端点接近 ±100。
5. **逐个检查四路拨杆**：A / B 档应分别为 `-1 / 1`；高/高或低/低均应显示 `2`，且不应长期出现。
6. **逐个检查四个按键**：`button_state` 中释放为 `0`、按下为 `1`；每次短按后确认对应 `button_toggle_state` 在 `0` / `1` 间翻转。SW1 是右摇杆按键，SW2 是左摇杆按键。
7. **确认业务状态**：拨杆使用 `toggle_switch_state`；瞬时按键的无线业务状态使用 `button_toggle_state`，不要将仅用于排查接线的原始变量或短暂物理按下状态直接用于后续业务。

## 无线数据包调试

组包后可在 Watch 中观察：

```c
wireless_control_last_frame_valid
wireless_control_last_frame
wireless_control_diagnostics
```

`wireless_control_last_frame_valid == 1` 表示至少已经完成过一次 14 字节控制帧组装。将 `wireless_control_last_frame` 以十六进制查看，应依次为 `A5 5A version type sequence 06 left_y left_x right_y right_x switches buttons_status crc_lo crc_hi`。
