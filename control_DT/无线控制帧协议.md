# 无线遥控控制帧协议（发送端设计）

> **状态：E34-1 发送端已接入。** `main.c` 以 100 Hz 采集并消抖输入，`wireless_control.c` 以 50 Hz 尝试组包并调用 `HAL_UART_Transmit()` 通过 E34-1 / USART1 发送。接收端尚需按本文实现解析、失联超时和安全动作；不得直接收发 C 结构体，以免受字节对齐、枚举宽度和端序影响。

## 1. 数据来源与发送流程

每个控制帧必须使用同一轮输入扫描后的**稳定值快照**，不得混用原始 ADC 值、未消抖状态或跨周期数据：

```text
每 10 ms：Joystick_Update() + ToggleSwitch_Update() + Button_Update()
                        │
                        └─ 读取 debug.joystick.value、debug.toggle_switch.state、debug.button.toggle
                                      │
                                      └─ 组装 14 字节控制帧 → 等待所选 E34 可发送 → UART 发送
```

| 控制帧字段 | 当前数据源 | 发送前要求 |
|---|---|---|
| 四个摇杆轴 | `debug.joystick.value.left_y`、`left_x`、`right_y`、`right_x` | 仅使用已中心校准并滤波后的 `-100～+100` 值。校准未完成时四轴均发送 `0`，并清除状态字的“校准有效”位。 |
| 四个两档拨杆 | `debug.toggle_switch.state.switch_1` ～ `switch_4` | 仅使用软件消抖后的稳定值；两档开关仅允许 A、B。任一无效电平组合必须编码为 `INVALID`，不能伪装成正常档位。 |
| 四个按键 | `debug.button.toggle.sw1` ～ `sw4` | 每次消抖后的“松开→按下”边沿翻转一次；上电均为 `0`，组包时持续发送锁存后的开/关状态。 |

`debug.joystick.raw`、`debug.joystick.filtered`、`debug.toggle_switch.raw`、`debug.button.raw` 和物理按键消抖结果 `debug.button.physical` 仅用于调试，不能直接发送给接收端。

## 2. 帧格式

控制帧采用固定 **14 字节** 的二进制格式。多字节 CRC 按低字节在前发送；其余字段均为单字节，因此不受 MCU 端序影响。

| 偏移 | 长度 | 字段 | 固定值 / 取值 | 说明 |
|---:|---:|---|---|---|
| 0 | 1 | `SOF0` | `0xA5` | 帧起始字节 0。 |
| 1 | 1 | `SOF1` | `0x5A` | 帧起始字节 1。 |
| 2 | 1 | `version` | `0x01` | 协议版本。 |
| 3 | 1 | `type` | `0x01` | 实时遥控控制帧。 |
| 4 | 1 | `sequence` | `0x00～0xFF` | 每成功提交一帧发送即加 1，溢出回到 0。 |
| 5 | 1 | `payload_length` | `0x06` | 载荷长度；接收端必须先检查该值。 |
| 6 | 1 | `left_y` | 有符号 `int8_t`，`-100～+100` | `debug.joystick.value.left_y`。 |
| 7 | 1 | `left_x` | 有符号 `int8_t`，`-100～+100` | `debug.joystick.value.left_x`。 |
| 8 | 1 | `right_y` | 有符号 `int8_t`，`-100～+100` | `debug.joystick.value.right_y`。 |
| 9 | 1 | `right_x` | 有符号 `int8_t`，`-100～+100` | `debug.joystick.value.right_x`。 |
| 10 | 1 | `switches` | 4 个 2 bit 档位码 | 编码见下一节。 |
| 11 | 1 | `buttons_status` | 按键位图和状态位 | 编码见下一节。 |
| 12 | 1 | `crc16_lo` | CRC 低字节 | 覆盖偏移 2～11。 |
| 13 | 1 | `crc16_hi` | CRC 高字节 | 覆盖偏移 2～11。 |

### 示例

若 `sequence = 0x2A`，四个摇杆值依次为 `+10`、`-20`、`0`、`+100`，四个拨杆依次为 A、B、A、B，`SW1` 与 `SW3` 的锁存状态为开且摇杆校准完成，则完整控制帧为：

```text
A5 5A 01 01 2A 06 0A EC 00 64 99 15 B3 08
```

其中 `0xEC` 是 `-20` 的二进制补码，`switches = 0x99`，`buttons_status = 0x15`。按第 4 节计算的 CRC 为 `0x08B3`，因此末尾按低字节在前追加 `B3 08`。

## 3. 拨杆、按键和状态位编码

### 3.1 `switches`：四个两档拨杆

每个拨杆使用 2 bit，低位在前：

```text
bit 1:0 = switch_1
bit 3:2 = switch_2
bit 5:4 = switch_3
bit 7:6 = switch_4
```

| 2 bit 值 | 含义 | 对应发送端枚举 |
|---:|---|---|
| `00` | 保留，发送端不会产生 | — |
| `01` | A 档 | `TOGGLE_SWITCH_POSITION_A` (`-1`) |
| `10` | B 档 | `TOGGLE_SWITCH_POSITION_B` (`1`) |
| `11` | 无效 | `TOGGLE_SWITCH_POSITION_INVALID` (`2`) |

> 不允许将枚举值直接移位后发送：A 档的 C 枚举值为 `-1`，直接转换会得到错误编码。必须显式映射为上表中的无符号 2 bit 码。

### 3.2 `buttons_status`：按键位图与状态

| 位 | 含义 | `0` | `1` |
|---:|---|---|---|
| bit0 | `SW1` 锁存状态 | 关 | 开 |
| bit1 | `SW2` 锁存状态 | 关 | 开 |
| bit2 | `SW3` 锁存状态 | 关 | 开 |
| bit3 | `SW4` 锁存状态 | 关 | 开 |
| bit4 | 摇杆中心校准 | 未完成或无效 | `debug.joystick.calibration.valid == 1` |
| bit5～bit7 | 保留 | 必须为 `0` | — |

bit0～bit3 是持续发送的锁存状态，而不是瞬时物理按键电平：发送端在每次消抖后的有效按下边沿翻转相应状态，上电默认全部为关。接收端应将这些位作为开/关状态使用；不能把每一帧的 `1` 当作一次新的按下事件。接收端在 bit4 为 `0` 时不得执行依赖摇杆轴的危险动作；建议将四个轴作为零值处理。接收端收到任一拨杆的 `00` 保留码或 `11` 无效码时，也应进入预先约定的安全处理，而不是按正常档位执行。

## 4. CRC 与接收校验

使用 **CRC-16/MODBUS**：初值 `0xFFFF`，多项式 `0xA001`（反射形式），不异或输出。CRC 的计算范围是 `version` 至 `buttons_status`，即偏移 **2～11** 的 10 个字节；不包含帧头与 CRC 本身。发送时先放低字节，再放高字节。

接收端必须按以下顺序处理数据流：

1. 搜索连续的 `0xA5 0x5A` 帧头；
2. 读取固定头部，确认 `version == 0x01`、`type == 0x01` 和 `payload_length == 0x06`；
3. 累计接收完整 14 字节帧，计算并比较 CRC；
4. 仅在 CRC 正确、字段范围合法后更新控制状态；CRC 错误、长度错误或版本未知的帧一律丢弃并重新搜帧头；
5. 使用 `sequence` 监视持续重复或长时间未更新的控制帧，但不能仅凭序号判断链路正常，仍应执行接收超时保护。

## 5. E34 / UART 发送约束

- 三个 E34 均已在普通通信模式（`M0/M1` 为低）初始化，UART 配置均为 **9600、8N1、无流控**。具体引脚对应关系见 [`IO.md`](IO.md)。
- 一次 14 字节帧在 8N1 UART 上需要传输 `14 × 10 = 140` bit，9600 bit/s 条件下仅串口线时长约 **14.6 ms**。因此，**当前 9600 bps 配置下不能以 100 Hz 可靠地发送此帧**；100 Hz 输入扫描仍可保留，但首次接入建议将控制帧发送周期设为 **20 ms（50 Hz）或更慢**。
- 实际发送间隔还必须为 E34 的空中发送时间和模块忙状态留出余量。发送前应按照所用 E34 型号的数据手册确认并检查对应 `AUX` 信号的可发送状态；模块忙时不应覆盖、拼接或丢弃正在发送的半帧。
- 本工程有三个 UART/E34 接口，但本协议的一帧控制数据应先明确发送到**一个选定的主链路**。只有在接收端和无线地址/信道已明确支持冗余接收时，才可向多个模块重复发送同一帧；不能把一帧拆分到不同模块。
- 初版可用阻塞式 `HAL_UART_Transmit()` 验证链路。量产或更高发送频率应使用 DMA/中断发送和独立发送缓冲区，并在上一次发送完成前禁止复用该缓冲区。

## 6. 发送端实现顺序

本工程已新增独立的 `Core/Src/wireless_control.c` 和 `Core/Inc/wireless_control.h`，集中管理帧组装、CRC、发送节流与模块状态；不要把协议字节拼接散落在 `main.c`。

```c
/* 每 10 ms 扫描输入；发送周期独立限制为 20 ms 或更慢。 */
if ((HAL_GetTick() - input_tick) >= 10U)
{
    input_tick += 10U;
    (void)Joystick_Update();
    ToggleSwitch_Update();
    Button_Update();
}

/* 内部以 20 ms 周期读取稳定输入、组装 14 字节帧、
   检查 E34-1 AUX，并调用 HAL_UART_Transmit()。 */
WirelessControl_Update();
```

实现时应特别核对：

1. `int8_t` 轴值按二进制补码原样写入，而不是以 ASCII 字符串发送；
2. `switches` 使用显式枚举映射；
3. `buttons_status` 的保留位始终清零；
4. 发送端会将每次已组装的原始 14 字节帧复制到 `debug.wireless.last_frame`，并置位 `debug.wireless.last_frame_valid`，可直接在调试器中按十六进制核对；
5. 代码仅在 `HAL_UART_Transmit()` 返回 `HAL_OK` 后递增 `sequence`；
6. UART 返回错误、模块忙或 CRC 组装失败时，不发送残帧；
7. 接收端必须实现独立的失联超时与安全动作，发送端持续发帧不能替代失联保护。

## 7. 联调验收

1. 上电后保持摇杆居中约 320 ms，确认 `debug.joystick.calibration.valid == 1`，再开始检查正常控制帧。
2. 通过串口抓包确认帧长恒为 14 字节、帧头为 `A5 5A`、版本/类型/长度为 `01 01 06`，且 CRC 正确。
3. 分别将每个摇杆轴移动到正、负方向，确认接收端得到相同的有符号值和已约定的正方向。
4. 依次切换每个拨杆的 A / B 档，确认相应 2 bit 字段为 `01 / 10`；将两触点同时悬空（高/高）或同时短接到地（低/低）时，应看到 `11` 并触发接收端安全处理。
5. 分别短按 SW1～SW4，确认 `buttons_status` 的对应 bit 在每次有效按下后于 `0 / 1` 间翻转，并在松手后保持；再次短按应翻回原状态。bit4 应在中心校准完成后置 1。
6. 在无线链路中断、拔掉模块或使 CRC 出错时，确认接收端在项目约定的超时时间内进入安全状态。
